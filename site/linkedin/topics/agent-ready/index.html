Speak the agent protocols, in one command

Each tile is what an agent reaches for. The right-hand link is the AILANG primitive that produces it — usually ailang serve-api, which emits all four at once from your typed function signatures.

ailang serve-api ⟶ REST + MCP + A2A + OpenAPI

One command, four protocols, zero glue code.

Point ailang serve-api at a directory of .ail modules. It exposes every exported function as a REST endpoint, an MCP tool, an A2A skill, and an OpenAPI 3.1 schema simultaneously. The same module runs in three places — native CLI, Cloud Run container, browser WASM.

Serve API guide ↗
func price(sku: string, qty: int) -> Money ⟶ openapi.json

OpenAPI 3.1 is generated from your Hindley-Milner signatures.

Function types are the API spec. A function's parameters, return type, and effect row determine paths, request bodies, response schemas, and security requirements automatically. Swagger UI is hosted at /api/_meta/docs; ReDoc at /api/_meta/redoc. No separate spec file to drift.

Interactive docs ↗
POST /mcp/ ⟶ Model Context Protocol

Your typed functions become MCP tools.

Claude Desktop, Cursor, Cline, and any MCP-aware harness can call your AILANG functions directly. Arguments are validated against the same requires contracts the REST endpoint enforces. Run as HTTP at /mcp/ or stdio for desktop hosts.

Protocol support ↗
GET /.well-known/agent.json

Agent-to-Agent discovery comes for free.

serve-api writes the A2A agent card automatically — capabilities, skills, schemas, and authentication metadata all derive from your module exports. Agents that follow the A2A discovery convention land on a complete, machine-readable description of what you offer.

A2A in serve-api ↗
requires { ... } ⟶ JSON Schema constraints

Contracts are agent-visible guarantees, not server-only checks.

Your requires and ensures clauses surface in the OpenAPI spec as JSON Schema constraints, so an agent calling your endpoint knows what's valid before it tries. Invalid requests get rejected by the runtime; valid ones come with a contract on what shape the response has.

Contracts & verification ↗
std/stream ⟶ text/event-stream

Streaming endpoints are typed too.

std/stream exposes SSE and WebSocket as a single Stream effect. Handlers receive typed event values, not raw bytes; back-pressure is in the effect signature. Agents reading incrementally get the same contract guarantees as a single-shot request.
